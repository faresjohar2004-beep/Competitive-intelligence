CONDENSED REPORT — Astra OS Product Intelligence, 2026-08-24
====================================================================

WHAT ASTRA OS ACTUALLY IS
A daily identity-transformation habit app (web SPA + Expo mobile) built on a promise -> actions -> AI-missions -> reflection loop, with five tracked life scores, server-enforced streaks + a monthly freeze, unlockable chapters, and AI-framed identity artifacts (coach, letters, biography), monetized via a Stripe "Pro" tier that is fully wired on web and entirely absent on mobile.

CURRENT USER JOURNEY
Web: Landing -> 3-step card onboarding -> Dashboard daily ritual -> broad secondary exploration (12 pages). Mobile: email/password sign-in -> 3-step free-text onboarding -> 5 tabs (Dashboard/Actions/Missions/Coach/Profile), with 8 web surfaces absent and the Dashboard read-only (Actions is the only logging screen).

STRONGEST FEATURES
Real core loop (score math, streak state machine, promise reconciliation on web); genuinely context-aware Coach (coaching.ts:13-80, injects 4 live data sources into a real gpt-4o-mini call); server-enforced streak freeze; excellent idempotent account deletion on both platforms; real, unit-tested server-side push pipeline; clean auth (no IDOR, no mass-assignment, admin routes properly role-gated, no secrets in code).

WEAKEST FEATURES
Web Settings "Save Changes" is inert with a hardcoded name "User" (Settings.tsx:50,52). Future-Self Projection, Letters, and Biography are sold as AI but contain zero AI (ai.ts:209-262, 353-383). Life Map history fabricates a 30-day trend with Math.random() (lifeMap.ts:32). Admin metrics' impact totals are hardcoded to 0 (admin.ts:57-58). Two internal links 404 to a mis-themed dev-copy error page.

FUNCTIONAL vs PARTIAL FEATURES
Functional: onboarding (with caveats), dashboard core loop, action logging (web), missions, chapters, evidence, reflections (web), coach chat, share (text), upgrade/checkout, streak freeze, push infra, account deletion. Partial/fabricated: Future-Self Projection (no AI), Life Map history (random), Timeline (stubbed arithmetic), Letters/Biography (templated), admin metrics (hardcoded 0), mobile action logging (no mission reconciliation), the entire mobile monetization layer (absent).

BIGGEST UX FRICTION
The inert Settings save and the two 404 links are the most discoverable breakages. The more damaging frictions are silent: on mobile, logging an action does not move your score (only 1 of 5 query keys invalidated, actions.tsx:100-106); a failed coach send destroys your typed message; a transient /me error ejects you back into onboarding and overwrites your profile (_layout.tsx:134-138).

BIGGEST RETENTION RISK
Two compounding: (1) mobile push almost certainly never delivers — getExpoPushTokenAsync is handed a Replit repl id as the EAS projectId and the failure is swallowed (useNotifications.ts:42-44), so the 7pm-reminder return mechanism is silently dead on mobile; (2) the still-unfixed mobile promise-reconciliation gap — mobile action logging never calls completeMission (actions.tsx:144-200), so the critical mission stays permanently incomplete for mobile-first users, a regression of a bug class two memory notes document as fixed on web.

BIGGEST COMMODITY RISK
The mechanical skeleton (streaks, logging, badges, journal, chat coach) is category-standard; the claimed AI-personalized differentiation is substantially templated and rendered indistinguishably from real AI. If surfaced (e.g. the mobile letter that literally says "Generated from your real scores... not a template" while being a random template, profile.tsx:524), this undermines the core pitch more than any missing feature.

STRONGEST DIFFERENTIATOR
The Coach's live context injection — today's actual missions + completion flags, today's actions, current scores, and a memory digest fed into every gpt-4o-mini conversation (coaching.ts:13-80). Genuinely differentiated and genuinely working when OPENAI_API_KEY is configured (4 sources, not the 3 the prior report credited).

WEAKEST DIFFERENTIATOR
"Future Self Projection" — marketed and Pro-gated as a premium AI insight, but 100% formula plus a single canned narrative string identical for every user, with no AI call anywhere in its path (ai.ts:353-383).

IDENTITY SYSTEM ASSESSMENT — 48/100
Corrected from the prior report: currentIdentity/desiredIdentity are NOT dead schema — the web client sends them but the server never reads them (users.ts:49), so both columns are permanently NULL and the personalized identity statement silently never renders (falls back to a career-derived string). Web (controlled vocabulary) and mobile (free text) onboarding diverge, and the upsert lets the last device clobber the other's identity model. A real chapter/biography arc keeps this above 40.

FAILURE RECOVERY ASSESSMENT — 50/100
Excellent for account deletion; improved on web (Dashboard + Reflections now toast on error). Still absent on web Actions/Coach/Letters/Biography/Missions and on ALL 12 mobile mutations (silent console.error). No global API error handler, 12/16 route files without try/catch, and the two core write paths (POST /actions, POST /missions/complete) run 8-10 writes with no transaction -> partial-write corruption then double-credit on retry.

TOP 5 PRODUCT PROBLEMS
1. CRITICAL — CORS origin:true + credentials:true with cookie auth (app.ts:61): any site a logged-in user visits can read their data and call DELETE /users/me. One-line fix; do it first. (NEW)
2. The paywall is client-side only — no route enforces isPro; every Pro feature is free via curl, and mobile gives them all away. Compounded by users.is_pro never being written yet being the Stripe-outage fallback, silently downgrading paying users (stripe.ts:19,68). (NEW — direct revenue loss)
3. "AI" features with no AI (Future-Self Projection, Letters, Biography), one denying it's a template; plus random-seeded scores shown as measurements across 6 surfaces incl. a shareable card. (Trust/legal exposure)
4. Mobile core-loop breakage: action logging never reconciles the critical mission (actions.tsx:144-200); score doesn't move after logging (stale invalidation); push likely never delivers (projectId bug); zero onError anywhere.
5. Data model has zero indexes and zero unique constraints on any per-user-per-day key (missions/biography/reflections/milestones/future_self/life_map/user_chapters all read-then-insert) -> duplicate rows and defeated idempotency; plus one fully dead table (life_map_history) and 19 dead columns.

TOP 5 PRODUCT OPPORTUNITIES
1. Security + revenue in one sprint: replace origin:true with an allowlist; add server-side isPro checks (and a sellable-priceId allowlist) to the 4 Pro routes; start writing users.is_pro. High impact, low effort.
2. Fix the cheap high-visibility trust breaks: wire the Settings save button; fix /trajectory->/timeline and /future->/future-self; re-theme the 404 page.
3. Close the mobile parity gaps: call completeMission in actions.tsx success; invalidate all 5 query keys; fix the EAS projectId; add onError toasts.
4. Resolve the AI-honesty gap: either wire Letters/Biography/Projection to the callOpenAI path that already exists three functions away, or relabel them honestly. /life-map/history is the cheapest — the real table is already defined, migrated, and imported.
5. Add the missing DB constraints + indexes: unique on every (user_id, <day-or-key>), plus (user_id, completed_at) on actions. Kills the duplicate-row and double-credit classes and fixes the worst query hot paths.

IMMEDIATE RECOMMENDATIONS
