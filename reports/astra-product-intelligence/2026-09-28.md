WHAT ASTRA OS ACTUALLY IS
A daily habit/identity-change app (web + native mobile, Clerk-gated) built around a promise→action→evidence→score→streak core loop, wrapped in an AI coach, AI-written future-self letters, an AI-generated daily biography, and an unlockable chapter system. Positioned explicitly as an "identity OS," not a task manager (Landing.tsx:252-256).

CURRENT USER JOURNEY
Landing page → 3-question onboarding (guest mode) → Clerk signup with auto-resumed answers → pre-seeded Dashboard → daily loop of set-promise/log-action/reflect, with secondary navigation into Missions, Life Scores, Letters, Biography, Timeline, and Hall of Regret. Mobile mirrors this across 5 tabs (Home, Actions, Missions, Coach, Profile).

STRONGEST FEATURES
1. The core promise/action/evidence/score loop — fully real, cross-verified across web, mobile, and backend, no mock data.
2. Account deletion — a genuinely robust Stripe+Clerk+DB purge with an idempotent 10-minute cron retry worker.
3. AI coach context injection — assembles real missions, actions, and scores via Promise.all before every AI call; the strongest "AI" claim in the product that's actually true.

WEAKEST FEATURES
1. Settings' "Save Changes" button — fully decorative, no click handler at all.
2. Life Map "history" — backend fabricates it with Math.random() while the real DB table for it sits completely unused; the frontend doesn't even call the endpoint today.
3. Missions.tsx's mission-complete call (web) — has no mutation-options object at all, the weakest error/feedback handling of any core-loop action in the app.

FUNCTIONAL VS PARTIAL FEATURES
Functional (real, live-data): Dashboard, Actions, Missions, Future Self scores, Chapters, Biography, Coach, Evidence Vault, Reflections, Share, Stripe billing, Account Deletion, Push Notifications, Promise Streak, all 5 mobile tabs.
Partial / fabricated: Settings (dead save button), Life Map history (random + orphaned), Future Self "AI Projection" (deterministic formula, mislabeled as AI), Timeline "Where You're Headed" (hardcoded offsets), Letters emotional tone (random) and paywalled teaser (fake dated "locked" letters implying unread letters that don't exist), Landing page + in-app "studies show" statistics (fabricated, no data source).

BIGGEST UX FRICTION
Two confirmed broken links that fire right after positive-reinforcement moments: Reflections' "See Your Progress" (→ /future, 404) and Dashboard's "View your trajectory" (→ /trajectory, 404, newly discovered this week — present since 2026-08-12 but not previously reported). Compounded by silent failures on the app's own most-core action: the dedicated Actions page's log-action call has no error feedback at all.

BIGGEST RETENTION RISK
Confirmed this week (previously only suspected): the mobile Missions tab's Critical Mission completion never invalidates the React Query cache keys the Home tab's "Yesterday's Promise" card reads from (useMissions.ts:44-46). A user can complete their mission and still see a stale, contradictory "promise pending" state on their own home screen — directly undermining the app's central "I kept my promise" payoff moment. The regression tests added alongside recent promise-streak work do not cover this path, so it remains unfixed despite commits that looked like they targeted exactly this problem.

BIGGEST COMMODITY RISK
Score 62/100 (unchanged). Streaks, check-ins, and AI chat are commodity mechanics in this category; the product's real moat is its identity-narrative layer, which is only partly genuine (see Weakest Differentiator) and cannot currently be measured or improved with data, since there is no analytics/telemetry infrastructure anywhere in the codebase.

STRONGEST DIFFERENTIATOR
The AI coach's real-time context injection (genuinely assembles live mission/action/score state, not a generic chatbot) and the "Hall of Regret"/"Courage Challenge" loss-aversion mechanics (missions.ts:318, Missions.tsx:431-533) — real, computed, and not typical of commodity habit-tracking apps.

WEAKEST DIFFERENTIATOR
The "AI Projection" of your future self is a deterministic arithmetic formula on your current scores with no model call and no trend modeling (lib/ai.ts:353-383) — marketed as AI, isn't one. Compounded by fabricated statistical claims scattered through both the landing page and the authenticated app itself (not just the marketing surface, as last week's report implied).

IDENTITY SYSTEM ASSESSMENT — 72/100
Genuinely load-bearing (real identity statements, Evidence Vault, AI letters/biography grounded in real activity), undermined by fabricated onboarding demographic defaults and a captured-but-unrendered profile field. Refinement this week: the "profile photo" is sourced from Clerk OAuth, not an in-app capture flow, and the image-picker dependency for such a flow is dead/unused.

FAILURE RECOVERY ASSESSMENT — 55/100
Excellent for account deletion (idempotent, cron-retried); weak for the highest-frequency actions (action logging, mission completion) — no custom error handling or logging in either route, though Express 5's default handler prevents a true unhandled crash (a nuance, not a fix).
