WHAT ASTRA OS ACTUALLY IS
A daily habit/identity-change app (web + native mobile, Clerk-gated) built around a promise→action→evidence→score→streak core loop, wrapped in an AI coach, AI-attempted daily missions, nominally-AI future-self letters and a biography, a deterministic "AI Projection," and an unlockable chapter system. Positioned as "an OS for identity change" (Landing.tsx:253,255), not a task manager.

CURRENT USER JOURNEY
Landing page → 3-question guest onboarding → Clerk signup with auto-resumed answers → pre-seeded Dashboard/Home → daily loop of promise/action/reflect, with secondary nav into Missions, Life Scores, Letters, Biography, Timeline, Hall of Regret. Mobile mirrors this across 5 tabs.

STRONGEST FEATURES
1. Core promise/action/evidence/score loop — fully real, cross-verified across web, mobile, backend.
2. Account deletion — robust Stripe+Clerk+DB purge with idempotent cron retry, on both platforms.
3. AI coach context injection — the one "AI" claim in the product that is both marketed and genuinely true.

WEAKEST FEATURES
1. Settings "Save Changes" — fully decorative; hardcoded name field; unlinked label.
2. Backend input validation — systemically absent on every route despite ready-made schemas.
3. Letters and Biography generation — marketed as "AI-generated" in the OpenAPI spec itself, but make literally zero model calls, ever (new finding this week, escalating a previously-isolated issue).

FUNCTIONAL VS PARTIAL FEATURES
Functional: Dashboard, Actions, Missions (real AI attempt + sane fallback), Future Self scores, Chapters, Coach (real AI), Evidence Vault, Reflections, Share, Stripe billing, Account Deletion, Push Notifications, Promise Streak, all 5 mobile tabs.
Partial/fabricated: Settings (dead save), Life Map history (random + dead on web), Future Self "AI Projection" (deterministic, mislabeled), Timeline (hardcoded offsets, mislabeled), Letters (random templates, zero AI calls, fake-dated teaser when 0 real letters), Biography (random templates, zero AI calls — same category as Letters, newly confirmed this week), initial Life/Future-Self score seeding (random, not onboarding-derived), Landing + in-app Dashboard fabricated statistics.

BIGGEST UX FRICTION
Two confirmed broken links (/future, /trajectory) still firing right after positive-reinforcement moments, four straight weeks unfixed, compounded by inconsistent-to-zero user-facing feedback on failed core-loop mutations — worst on mobile's Home tab, which has no error handling of any kind on its promise-sealing flow.

BIGGEST RETENTION RISK
The mobile promise-reconciliation bug, root-caused at the line level (useMissions.ts:44-46 invalidates only ['missions']) and confirmed to have a second instance (actions.tsx never invalidates stats/future-self keys) — so a user can complete their mission and still see stale, contradictory state across the promise card, streak, and score, not just one element. Unfixed for a fourth consecutive week.
