CONDENSED REPORT — Astra OS Product Intelligence, 2026-09-14
=================================================================

WHAT ASTRA OS ACTUALLY IS
A daily identity-transformation habit app (web SPA + Expo mobile) built on a promise -> actions -> AI-framed missions -> reflection loop, with five tracked life scores, server-enforced streaks + a monthly freeze, unlockable chapters, and AI-branded identity artifacts (Coach, Letters, Biography, Future-Self Projection), monetized via a Stripe "Pro" tier that is fully wired on web billing but not server-enforced as a feature gate, and entirely absent on mobile.

CURRENT USER JOURNEY
Web: Landing -> 3-step card onboarding -> Dashboard daily ritual -> 12-page secondary exploration. Mobile: email/password sign-in -> 3-step onboarding -> 5 tabs (Dashboard/Actions/Missions/Coach/Profile), with 8 web surfaces absent and the Dashboard read-only (Actions is the only logging screen, and it doesn't reconcile with the promise/mission state — re-verified this run).

STRONGEST FEATURES
The Coach's live context injection (coaching.ts:13-80, re-verified this run) — the one genuinely-AI, genuinely-differentiated surface. Also solid: server-enforced streak/freeze logic, idempotent cross-system account deletion, a unit-tested push pipeline (server side), and clean core auth with no IDOR observed.

WEAKEST FEATURES
Web Settings save is inert (Settings.tsx:52). Future-Self, Letters, and Biography are marketed as AI but contain zero LLM calls (letters.ts:41, ai.ts:89,92,228,250,261, templated patterns re-verified this run). Life Map history and initial onboarding scores are Math.random()-generated (lifeMap.ts:32, users.ts:72,101). Admin metrics hardcode all five impact totals to 0 (admin.ts:57-58). /trajectory is a dead nav link (Dashboard.tsx:1352,1357).

FUNCTIONAL VS PARTIAL FEATURES
Functional: onboarding, web dashboard core loop, web action logging (reconciled), missions, chapters, Coach chat, checkout/upgrade billing, streak freeze, server-side push infra, account deletion. Partial/fabricated: Future-Self Projection (no AI), Life Map (random), Biography/Letters (templated), admin metrics (hardcoded 0), mobile action logging (no mission reconciliation), the entire mobile monetization layer (absent), mobile push delivery (wrong project-id, likely non-functional).

BIGGEST UX FRICTION
The inert Settings save and the /trajectory dead link are the most discoverable breaks. More damaging structurally: mobile gives zero feedback on mutation failure (no onError handling found outside ErrorBoundary.tsx) and zero visible confirmation that logging an action affected your mission/promise state.

BIGGEST RETENTION RISK
Mobile push is very likely non-functional — getExpoPushTokenAsync is handed a Replit repl ID as the EAS projectId (useNotifications.ts:43, re-verified this run), silently disabling the primary mobile re-engagement channel. Compounding this, mobile action logging still never calls completeMission, so mobile-first users can never see their promise marked kept.

BIGGEST COMMODITY RISK
The mechanical skeleton (streaks, logging, badges, chat coach) is category-standard. The claimed AI-personalization differentiation is, for 3 of 4 relevant features, templated/randomized and visually indistinguishable from real AI to an end user — re-confirmed across all Math.random() call sites this run.

STRONGEST DIFFERENTIATOR
The Coach's real-time context injection: today's actual missions + completion flags, today's actions, current 5-axis scores, and a memory digest fed into a live LLM call (coaching.ts:13-80). Genuinely working when OPENAI_API_KEY is configured (live output quality NOT_INSPECTED this run — no API access in this environment).

WEAKEST DIFFERENTIATOR
"Future Self Projection" — marketed and Pro-gated as a premium AI insight, backed by arithmetic and canned templates with no LLM call anywhere in its path.

IDENTITY SYSTEM ASSESSMENT — 48/100
Identity-statement fields are a silent write-drop: re-verified this run that no such field is referenced anywhere in routes/users.ts, so any personalized identity statement cannot reflect real user input.

FAILURE RECOVERY ASSESSMENT — 50/100
Excellent for account deletion; improved on web Dashboard/Reflections (toast on error). Still absent on 14/18 server route files and on effectively every mobile mutation. Re-confirmed this run: neither POST /actions nor POST /missions/complete uses a DB transaction, despite the latter performing 6+ sequential dependent writes (insert action, 2x update futureSelf, update lifeMap, 2x update users, insert userChapters, insert milestones) — a mid-sequence failure can leave streak/score/chapter state inconsistent.
